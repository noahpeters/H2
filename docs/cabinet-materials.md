# Cabinet material definitions and mapping

Cabinet Designer remains a Three.js designer. This change adds material data and UV mapping; it does not add a renderer or a Render Photo action. Geometry, dimensions, visibility, object/motion transforms and camera controls remain authoritative in their existing paths. No displacement map is supported.

## Saved specifications

`MaterialDefinition` is a JSON-only, version-1 schema: stable selection ID, label, substrate type/species/cut, optional finish system/color, PBR base tint/roughness/metalness/IOR/specular intensity, and explicit albedo/normal/roughness/AO asset slots. Each asset requires its URI and provenance source/license. Any populated slot requires a positive `textureSize` with width, height and `in`, `mm` or `m` units. Width is across grain and height is along grain; every slot uses the same tile footprint and alignment. Optional `textureGrainAxis` records the source image's along-grain direction (`u` or `v`, default `v` for older definitions). This source fact is separate from a part's X/Y/Z grain direction. Width always means across-grain physical extent and height along-grain extent, even for source-U images. Normal maps use tangent space, roughness maps use Three.js's green channel, AO uses red, and albedo uses sRGB. Other maps are linear data. Base color remains the color-only fallback. Optional `pbr.albedoTint` supplies an independent multiplier for a complete albedo map; it defaults to base color for older specifications. Texture provenance can include `notes` documenting source limitations. Normal maps must use the OpenGL convention.

`RoomElement.materialDefinition` is an optional immutable specification snapshot. Its ID must match `material` (default `rift-white-oak`); saved-room validation rejects mismatches and invalid definitions. JSON save/load and existing study migration retain the snapshot. Changing the material or paint selection clears the previous snapshot. This foundation exposes the schema in code; it adds no asset-authoring UI.

Legacy room version 2, material IDs, catalog colors and paint choices remain supported without a destructive migration. Missing definitions resolve through `CABINET_MATERIAL_DEFINITIONS`. Missing roughness keeps each existing path's value: standard boards/toe kicks 0.6, standard front panels 0.65, custom-unit parts 1. Missing metalness stays 0. IOR/specular use Three.js defaults unless explicitly supplied, in which case the same Three.js path creates a `MeshPhysicalMaterial`. No texture size means existing UVs remain untouched. Missing assets mean no maps are assigned. A failed load drops that slot, retains the color fallback and records its URI in material `userData.textureErrors`.

## Application per part

Grain is separate from the base definition. `CabinetPart.materialApplication` persists local grain axis, a quarter-turn texture rotation and optional physical U/V offset. Standard generated parts resolve roles deterministically. Local X is width, Y height, Z depth; standard/appliance geometry is in metres and custom geometry in inches. The existing custom-body conversion to metres, reversed Z and all placement/motion transforms are applied after stock-space mapping.

| Part | Default grain axis |
| --- | --- |
| Doors, stiles, vertical ends | Y |
| Drawer fronts, rails, shelves | X |
| Drawer box sides generated by the motion rig | Z |
| Other boards | X when height is the smallest dimension; otherwise Y |

UVs project local coordinates onto each face plane, divided by the explicit physical tile footprint. The centred local origin sets the tile phase; the saved physical offset adjusts that phase. Quarter-turn rotation acts on physical coordinates before tile-size division. On a face perpendicular to the grain axis, the first remaining in-plane axis is used as the V axis. This is an explicit fallback, not a claim that a long-grain asset represents end grain. Verified end-grain assets and a separate end-face policy remain future work.

Merged custom shaker geometry carries a per-vertex grain-axis attribute so rails and stiles retain different orientation. A saved explicit part-axis override applies to the entire part. Mapping modifies only UVs and application metadata, never positions or dimensions. Curved profiles retain their existing stock-space UVs while geometry is deformed: this is deterministic but does not promise constant arc-length texture scale across curves. Curve-aware physical unwrapping remains future work.

Part scale lives in geometry UVs, not shared texture repeat/rotation. The built-in loader shares textures by URI and slot color space with reference-counted ownership. Slot configuration is set once and never changed per part. Custom source providers are cloned before configuration. Disposing one material cannot dispose another's maps; the last owner releases the GPU texture. Static choice thumbnails wait for map loading (including failure fallback) before capturing pixels. Motion-generated drawer boards and tambour slats get their own materials and physical UVs rather than inheriting front UVs.

## Explicit catalog and white oak preview

All six material IDs resolve through the richer catalog and the live material factory. For example, `walnut` explicitly identifies wood and species Walnut, retains the existing `#72513d` visualization tint, and leaves cut and finish unspecified. White oak cuts come from the existing rift/plain selection labels. Catalog tints and historical roughness values are visualization defaults, not calibrated finish measurements.

`plain-white-oak` now bundles Poly Haven's **White Oak Veneer**, by Jenelle van Heerden, under CC0-1.0. Source: https://polyhaven.com/a/white_oak_veneer; license: https://polyhaven.com/license. Four unmodified 1K JPG maps (diffuse, OpenGL normal, roughness, AO) share the provider's 500 × 500 mm footprint. They are served from this site's public assets, with no Cloudflare credentials or third-party runtime requests. 1K limits this set to approximately 16 MiB of base GPU texture data (plus mipmaps), shared across cabinet parts. Download URLs, dimensions and SHA-256 hashes are recorded in `public/studio/materials/white-oak-veneer/provenance.json`.

**Cut limitation:** the provider identifies white oak and raw veneer but does not specify the saw cut. The designer selection still records plain-sawn design intent; this is a white oak visualization whose cut is unverified, not a certified plain-sawn sample. A note appears beside the selected material in both editors. No branded finish, Rubio parameters, calibrated coating response or end-grain asset is represented. The maps are not generated or altered by AI. Rift white oak stays color-only until a licensed cut-specific texture is available; paint grade retains its original color workflow.

White albedo tint and roughness 1 are neutral multipliers preserving the source maps, not measured finish specifications. Failed albedo loading restores the original beige visualization color. Existing explicit saved definition snapshots remain authoritative, including color-only snapshots. Designs containing only the `plain-white-oak` selection resolve to the updated catalog; reselecting the material clears an older snapshot if the user wants the new preview. There is no displacement or geometry change.

## Verification

`materialRendering.test.ts` exercises specification and saved-design round trips, legacy defaults, validation, unchanged geometry, cross-unit physical scale, representative part grain conventions, merged shaker rail/stile mapping, explicit rotation/offset, standard/custom/appliance integration, PBR opt-in and texture isolation/disposal. Run `npm run verify`; the installed pre-push hook also runs lint and the full test suite.

## Live scene updates

The room viewport keeps one Three.js renderer, canvas, camera, controls and animation loop for its mounted lifetime. Camera changes and scene edits invalidate rendering; an idle viewport skips GPU redraws while controls continue checking damping. Canvas dimensions are changed only when the host size actually changes.

`StudyScene` reuses room/cabinet geometry when only selection or placement changes. Exact transforms are updated on retained objects; dimensions, elevation-dependent hardware, material definitions, countertop cutouts and other geometry inputs still rebuild their affected objects through the existing factories. Replacement meshes retain their predecessors until all texture loads settle, and a revision check prevents older asynchronous results from restoring stale designs. Pending replacements survive drag updates without restarting their loads. Old meshes are disposed after replacement, keeping shared texture references alive throughout the transition. Selection lines, pending objects and shadow resources are released on unmount.

Regression tests cover repeated drags without mesh/map replacement or additional texture loads, stable renderer/camera/canvas lifetime, idle redraw suppression, asynchronous replacement, superseded loads, exact dimension changes and final disposal. These are automated lifecycle tests; live browser verification is still needed for the original drag recording on the deployed preview.


## Walnut, cherry, maple and representative rift oak

The existing selections now use Poly Haven's Walnut Veneer, Cherry Veneer and White Maple Veneer, respectively. All are CC0-1.0 assets by Jenelle van Heerden. Each set bundles four unmodified 1K JPG maps (diffuse, OpenGL normal, roughness, AO), its README and a provenance manifest with download URLs, SHA-256 hashes and dimensions. The walnut provider page lists a 1.8 m width and 5.7 px/cm at 1K; cherry and maple list a 1 m width and 10.2 px/cm. Their square source images imply square tiles at those physical widths. This basis is recorded explicitly rather than claiming a successful metadata API lookup.

| Selection | Source | Source grain | Across × along tile |
| --- | --- | --- | --- |
| Walnut | https://polyhaven.com/a/walnut_veneer | V (vertical) | 1800 × 1800 mm |
| Cherry | https://polyhaven.com/a/cherry_veneer | U (horizontal) | 1000 × 1000 mm |
| Maple | https://polyhaven.com/a/white_maple_veneer | U (horizontal) | 1000 × 1000 mm |
| Rift-white-oak representative preview | https://polyhaven.com/a/oak_veneer_02 | U (horizontal) | 1000 × 1000 mm |

Source grain was inspected on the actual albedo files. Geometry UVs transpose across/along coordinates for source-U materials; image files and shared texture transforms stay unchanged. This also preserves alignment with the corresponding tangent-space normal, roughness and AO maps. Older definitions without `textureGrainAxis` retain source-V behavior. Saw cut, botanical subtype and coating system are not inferred. Original preview colors remain fallbacks, and white albedo tint / roughness 1 remain neutral source-map multipliers. Saved color-only snapshots remain authoritative; reselect a wood to use the updated catalog.

### Rift-sawn white oak asset gap

No verified openly redistributable, physically scaled rift-sawn white oak set was located in this search. Poly Haven's existing White Oak Veneer does not identify its cut; generic oak or straight-grain images were not relabeled. A cut-specific commercial candidate exists at https://superellipse.co/en-us/products/white-oak-rift-sawn-wood-veneer, but its commercial license/account access is not an open license and permission to redistribute its source maps has not been established. No files from that provider are bundled. The user subsequently selected CC0 Oak Veneer 02 as a representative rift-white-oak preview. It uses the provider's 1 m footprint and inspected source-U grain. The catalog substrate remains the authoritative rift-sawn white-oak design selection, while the editor preview note and provenance explicitly state that the texture's white-oak species and cut are unverified. Existing color-only snapshots remain color-only; supplied saved texture definitions still take precedence. A verified rift-specific scan would improve material fidelity.

Additional regression tests verify each new set's integrity, serialization, legacy snapshots, slot semantics, fallback color and actual physical mapping on doors, drawer fronts, rails, stiles, shelves, ends and drawer sides, including non-square source-U footprints. Existing lifecycle tests now use explicit color-only snapshots, so adding production assets does not turn those synthetic tests into unresolved image loads.

The original Natural Walnut Veneer files remain available for saved material snapshots referencing their URLs; new walnut selections resolve to Walnut Veneer.

### Wider rift-white-oak search

A wider search covered CC0 libraries, commercial texture libraries, stock marketplaces and manufacturer scans. No verified open-licensed, real-sample rift-white-oak set with physical dimensions was found. Specific leads and blockers:

- Superellipse White Oak Rift Sawn Wood Veneer: https://superellipse.co/en-us/products/white-oak-rift-sawn-wood-veneer. Explicit white-oak/cut label, PBR maps and a 200 × 200 cm footprint. The FAQ restricts standalone map sharing (https://superellipse.co/en-us/pages/faq); browser delivery and public-repository redistribution need explicit permission. Real-sample acquisition provenance remains unverified.
- TurboSquid / propsny, 32 North American wood grain images: https://www.turbosquid.com/FullPreview/518178. Explicitly lists Rift White Oak and says the images are scans of actual veneer samples (1650 × 2550 px). Physical sample dimensions and full PBR slots are not specified. The license's WebGL/source-access restrictions require approval for our delivery path: https://blog.turbosquid.com/royalty-free-license/.
- Lightbeans / Elmwood Copal Stain on Rift Cut White Oak Woodgrain Laminate: https://lightbeans.com/en/texture/elmwood/elmwood-custom-blond-stain. This is a specific laminate/finish product rather than generic rift-white-oak timber. The texture terms prohibit redistribution without written consent and use promoting competing products: https://lightbeans.com/en/pages/texture-terms.
- FreeAlphas Close marked rift sawn: https://freealphas.com/a/close-marked-rift-sawn/. CC0 but an algorithmically generated grayscale pattern, not a verified white-oak sample or measured PBR set; unsuitable for the explicit real-material requirement.
- Manufacturer reference swatches (for example https://keystonewood.com/acceptable-rift-cut-white-oak-examples/) identify actual unfinished rift-cut white oak, but no redistributable map license or measured tile is established. They are research references only.

The concrete next acquisition path is permission for a verified scan (including web-delivery and repository rights, physical sample footprint and available maps), or an original measured photograph/scan of confirmed rift-sawn white oak. No restricted candidate maps above have been copied into production assets. The user-approved CC0 Oak Veneer 02 representative preview is now bundled with its limitations explicitly recorded.
